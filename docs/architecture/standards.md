## 统一原则

1. 模块围绕领域职责、状态与行为组织。技术分层放在领域内部，按实际复杂度引入。
2. 每个领域拥有明确的公开接口和状态归属；跨领域通过公开契约交互。
3. 依赖指向领域模型与能力接口；具体适配器由应用入口装配。
4. TypeScript 服务通过 Effect 提供依赖与资源生命周期，Go 使用普通构造函数并由 Wire 装配。
5. 跨语言协议独立于领域内部模型，边界负责转换、错误和取消语义。
6. Agent 常驻上下文保持简短，详细内容通过明确触发条件按需读取。
7. 事实以实现和正式契约为准，摘要保留来源并明确当前能力状态。

## 落地方式

完整目标是在职责稳定后按领域建立公开入口、局部说明和边界验证。

当前 TS 五个模块和 Go 契约边界已实现，兼容方式是保留旧公开入口：新增能力先声明职责、依赖和接口，逐步形成领域边界；现有文件可以继续承担框架初始化职责。改动涉及多个领域或多个层次时，在说明中记录原因和后续整理条件。

当前规范通过仓库指令、文档和评审执行。Go / TS 的声明式导入检查与接口替换测试已加入统一检查，覆盖范围见模块依赖说明。已提供显式环境的文件读取和固定展示预算；专用上下文索引展开、缓存和动态预算尚未实现，设计见 [运行时上下文方案](context-runtime-plan.md)。

## 变更验收

- 能说明新增或修改能力所属的领域、状态归属和公开接口。
- 依赖与接口变更有对应的消费方、错误和生命周期验证。
- 调整契约时同步修改实现、协议说明和必要的跨语言测试。
- 更新被影响的上下文摘要和读取触发条件，保留事实的唯一来源。
- 架构决策改变技术选型、领域所有权或兼容边界时，在 `docs/architecture/` 记录原因、替代方案和影响；普通实现选择在变更说明中交代即可。
