# Pi 运行时的渐进式上下文方案

状态：待实现方案。本轮只确定设计，现有文件工具与 16 KiB 展示预算继续可用。规则入口见 [披露规范](context-disclosure.md)。

## 目标与根本方案

新增独立的 context 模块，以 Effect 的 ContextService 契约提供索引发现与只读展开；实现依赖 FilesystemService，不直接读取 Node 文件，也不绕过环境路由。

宿主注册来源：sourceId、environmentId、入口路径、可展开的文档范围及简短描述。来源只能引用已注册环境；即使本轮都是 local，也始终保留环境名称，避免将不同目录中的同名文档混用。来源配置是新增能力，不在当前环境 JSON 中预留可被误认为已实现的字段。

| 层级 | 提供什么 | 触发方式 |
| --- | --- | --- |
| 常驻入口 | 简短约束、来源名称和索引入口 | 创建 Pi 会话时 |
| 主题索引 | 主题、触发条件、摘要、权威文档 ID | context_catalog 查询来源或主题 |
| 文档正文 | 被选中文档的一个有界片段 | context_read 使用 sourceId、文档 ID、偏移 |
| 任务证据 | 必要源码、测试或日志片段 | 已有文件工具和命令工具 |

Pi 当前 SDK 的 DefaultResourceLoader 支持 noContextFiles、agentsFilesOverride 和 appendSystemPromptOverride；源码入口为依赖包的 core/resource-loader。接入时由宿主明确选择受控 ResourceLoader，关闭自动全量上下文扫描，再注入短入口。现有自定义 ResourceLoader 不能被静默覆盖。

## 如何读取与保留来源

1. 宿主加载明确配置的索引，校验来源、文档 ID 和目标绑定，不启动全仓扫描。
2. Agent 先取得主题摘要，按任务选择文档；工具把文档 ID 解析到宿主登记路径，调用 FilesystemService。
3. 正文按 UTF-8 边界分段，返回 sourceId、environmentId、路径、字节范围、nextOffset 和该片段内容哈希。正文作为工具资料，不加入新的系统指令。
4. 每次调用检查单次和会话累计预算；未返回的必要内容通过续读显式获取，不宣称已完整阅读。
5. 跨模块问题沿索引展开相关契约，达到足够证据后停止读取。

首版建议单次 16 KiB、每次会话默认累计 64 KiB 的正文预算，均由宿主配置并与 Pi 剩余上下文共同约束；具体数值在实现与模型验收时固定。取消沿现有 Effect / Go 调用传递；未知来源和不可读文件明确失败。

缓存主要避免向模型重复发送同一片段。现有 Stat 的大小和修改时间只能作为变化提示，不能当作强版本保证；命中前仍需有界读取并核对片段哈希。跨分段读取不承诺文件快照，发现变化时告知重新读取，不拼接成一个声称一致的版本。后续若需要强缓存或快照，再扩展文件契约。

## 兼容方案

短期可以使用现有 filesystem_read 读取简短 AGENTS.md，再沿 docs/context/index.md 的链接展开，不新增运行时工具。这已经支持显式环境和续读，但缺少来源注册、累计预算、去重与阅读记录。它适合当前本地开发，不能描述为已经具备自动渐进式披露。

根本方案通过 ContextService 统一这些规则，同时继续保留普通文件工具。索引初期由宿主维护，不引入向量数据库或自动摘要服务。

## 实施顺序与验收

先实现来源注册、主题索引和只读展开，再加入累计预算与去重，最后评估任务命中率和上下文占用。测试至少覆盖：启动没有加载详细正文、只展开任务命中的主题、同路径不同环境不混用、文件变化后重新读取、中文分段续读、预算耗尽、取消和错误，以及自定义 ResourceLoader 兼容。
