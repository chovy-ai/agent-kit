# 对话界面与会话宿主

状态：已实现。读取触发：修改对话布局、执行记录、浏览器连接、恢复时序或网页宿主的选择。

## 决策与边界

默认界面采用仓库内的 React 展示层，基础组件与视觉规范使用 `@nextop-os/ui-system`。后端继续使用固定版本 pi-web-ui 的 Pi 会话服务；领域工具仍经 Pi extension、Effect 与 Go 执行。这样对话交互可以独立演进，不需要复制上游应用或改变执行接口。

根本方案是自有对话状态与展示，消费宿主的公开会话协议；兼容方案通过 `--ui classic` 使用原版页面。SDK、单次 CLI 和 Pi extension 的公开入口保持兼容。

| 所有者 | 职责 | 不拥有 |
| --- | --- | --- |
| `web/src/App.tsx` | 输入、环境选择、对话与工具展示、滚动和草稿 | 模型凭据、文件或命令执行 |
| `web/src/state.ts` | 会话快照与增量适配、输出预览、明确的取消识别 | 重试写操作或执行任务 |
| `web/src/session.ts` | 等待目标会话，避免临时空白快照覆盖历史 URL | 会话文件、服务端会话所有权 |
| `web/src/connection.ts` | Effect Scope 中的 WebSocket、订阅和重连 | 用户任务的自动重发 |
| pi-web-ui 宿主 | Pi 会话、流式事件、历史文件和已有取消流程 | Go 内部执行实现 |
| Agent Kit extension | 每个会话的工具应用、ManagedRuntime 和 Go Runner 生命周期 | 第二份 Pi 会话 |

## 状态流

```text
输入任务 + 选择环境 → prompt → Pi → Agent Kit 工具 → Go
                           ↓
                     快照 / 流式事件
                           ↓
               回复 + 可展开的执行记录
```

浏览器只连接同源 `/ws`，不持有 Sub2API Key。环境列表来自启动器生成的公开元数据，只包含名称与模型 ID；用户的选择随下一条 prompt 发送，具体工具参数仍由 Agent 显式传 `environmentId` 并交由 Go 验证。

适配器固定对应 pi-web-ui 0.104.4 的协议 29。快照是权威状态，增量按修订关联；缺失基线请求完整快照。增量只属于当前 conversationId，重复序号不重复拼接。Go 的命令预览为累计文本，覆盖旧预览。恢复 URL 指向的会话时，先取得列表并请求切换，等目标快照到达后才显示；找不到历史或恢复失败时保留可见提示。

停止按钮发送宿主已有的 abort 操作，不提前伪造工具终态。明确的中断文本转为“已停止”的展示，普通失败、超时和未确认状态继续保留错误信息。执行是否停止仍以实际工具和进程结果验收。已保存工具结果可从历史恢复；尚未持久化的取消预览只在当前页面保留。

前端构建目录与运行目录分离：启动器将 `web/dist` 复制到状态目录下的应用目录，再选择该目录作为宿主的静态根。运行后重新构建不会删除当前页面的环境配置或资产。更换界面代码后重新启动服务，已保存会话不随构建清理。
